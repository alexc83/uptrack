# Security reporting

Report sensitive vulnerabilities privately through [GitHub private vulnerability reporting](https://github.com/alexc83/uptrack/security/advisories/new). This repository's private reporting path was enabled and verified during PM01.

Do not publish confidential exploit details, credentials, tokens, certificate URLs or user information in public issues, PRs or logs. Use synthetic examples and sanitized evidence. A private GitHub Project does not make repository issues private. If the reporting form is unavailable, do not fall back to a public issue; ask the repository owner to restore the private channel before sharing details.

Public security/hardening issues are appropriate only for sanitized work. Distinguish confirmed behavior from hypotheses, state evidence limitations, and obtain owner authorization before testing external services or changing production assets.
